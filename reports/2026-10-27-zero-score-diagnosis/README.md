# 训练 prefix2 零分诊断

日期：2026-10-27。输入是已发布的 [2026-10-26 训练快照](../2026-10-26-train-prefix2/)，不是新实验，也不是测试集成绩。

## 结论

**没有发现评分器缺陷的证据。** 两臂均在 `user_stop` 正常结束，评分完整（每个子任务都有 `subtask_reward`）。零分与以下可观察行为一致：

| 实验臂 | 子任务 0（外卖） | 子任务 1（酒店） | 分数 |
| --- | --- | --- | --- |
| baseline | 已下单，但商品标签含 `高GI`，不符合健康/低 GI 约束 | 已下单并支付，但选择 JW 万豪，不是用户历史明确偏好的喜来登 | 0.0 / 0.0 |
| harness | 连续 4 次校验/兜底回复；最终状态中没有外卖订单 | 创建了未支付订单，品牌同样不是喜来登 | 0.0 / 0.0 |

因此这次试验说明的是**模型偏好遵循与执行检查的诊断问题**，不能说明 harness 有效或无效，也不能外推到测试集。

## 可核查证据

见 [diagnosis.json](diagnosis.json)。核心字段：

- `termination_reason = user_stop`，不是崩溃、超时或缺失评分。
- baseline 最终状态有 1 个外卖订单和 2 个酒店订单；外卖商品标签含 `高GI`；酒店品牌不是喜来登。
- harness 最终状态没有外卖订单；酒店订单状态为 `unpaid`；品牌不是喜来登。
- harness 轨迹中有 4 条“尚未执行/系统校验”类兜底回复，集中在需要先观察商品事实的外卖下单阶段。
- 两臂工具错误计数均为 0；问题不是工具返回错误，而是选择/约束遵循和检查阻塞。

`diagnosis.json` 使用 task ID 的 SHA-256 前缀，不含地址、姓名、用户画像或原始模型文本。分析脚本 [analyze.py](analyze.py) 可离线复现，只读取已发布的训练快照和训练集对应任务行。

另外，用 `vita_agent.traces` 对两臂训练结果重新导出规则技能：

- baseline：`exported=0`，`unsuccessful_without_known_tool_errors=1`
- harness：`exported=0`，`unsuccessful_without_known_tool_errors=1`

两臂都没有可识别的工具错误，所以规则提炼得到 0 条技能。不能用手工演示技能补足；LLM 反思需要真实模型请求，本次免费额度已耗尽，未执行。

## Token 与请求

已发布快照的预算 ledger 记录两臂共 **64 次已结算请求**，输入 **1,355,720** Token、输出 **12,249** Token。按当时 DeepSeek 峰时未缓存单价估算 **2.809432 CNY**，不是供应商账单。

本诊断从消息 `usage` 字段单独汇总到：

| 实验臂 | 输入 Token | 输出 Token |
| --- | ---: | ---: |
| baseline | 514,170 | 1,975 |
| harness | 813,034 | 3,999 |

消息级汇总低于 ledger，因为 ledger 还包含模拟用户、评测器、记忆抽取/重生成等请求；两者都不是新调用。

## 对后续实验的含义

1. 不能因为两组都 0 分就增加样本量或修改评分规则来“制造”提升。
2. 结构化记忆至少需要覆盖用户明确表达的品牌偏好；本轮新增了一个窄规则，把训练集约 17 条明确酒店品牌表述纳入 `hotel_brand` 软偏好（见 `docs/verification.md`）。这不是效果证明。
3. harness 的“缺少可信事实”阻塞需要给出可执行的下一步提示，并区分“需要先查询”与“确实缺信息”；否则会消耗轮次并可能导致子任务无订单。
4. 任何改动后必须新建计划，并在新模型上重跑 baseline；本报告不提供新模型分数。

## 边界

- 只有 1 个训练用户、2 个子任务、每臂 1 trial。
- update 子集也是 0.0，但只有 1 个用户，不能报告置信区间或总体结论。
- 没有 memory/skills/full 真实结果，没有测试集泄漏或测试集评测。
- 本报告不能证明任何模块带来提升。
